# 系统时间与启动保护

0.3.3 候选版在启动 MyBot 前检查系统时间，避免无效时钟导致 HTTPS 配对失败。默认继续使用系统已有校时服务；程序不会自动启动第二个 NTP 客户端，也不会修改时间服务配置或降低 TLS 校验要求。该逻辑仍需设备验证，结果见[验证矩阵](../validation/README.md)。

## 默认行为

只有网络可用且不处于 AP 配网期间，才开始计时。系统实时时钟达到 **2026-01-01 00:00:00 UTC** 即通过合理性检查；该门槛仅排除明显无效时间，不能证明时钟准确、NTP 同步成功或证书一定有效。

默认等待 30 秒，使用单调时钟计算等待预算，时钟校正不会改变预算。CLI `--time-sync-timeout SECONDS` 或环境变量 `RV1126B_TIME_SYNC_TIMEOUT` 可设置 1–300 秒，CLI 优先。网络丢失时取消当前等待及本应用启动的 helper；网络重新可用后重新计算完整窗口。AP 配网期间不消耗授时等待预算，也不运行 helper。

```sh
./run.sh --time-sync-timeout 60
```

系统时钟仍无效且等待超时，或显式 helper 启动/运行失败时，屏幕与标准错误报告原因，应用以非零状态退出，不继续启动 SDK。已有系统服务仍可继续工作；修复网络或校时条件后重新运行应用即可。

## 可选 BusyBox helper

只有系统没有运行现成校时服务、且确实需要应用负责一次性校时时，才显式选择 helper。`--time-sync-helper PATH` / `RV1126B_TIME_SYNC_HELPER` 必须是绝对的可执行文件路径，调用时不附带参数。时钟已经通过合理性检查时无需启动 helper。

仅在时钟无效且显式选择 helper 时，应用先通过 `/proc` 检查 `ntpd`、`chronyd`、`systemd-timesyncd`、`openntpd`。发现已有服务时继续等待它校时，不启动配置的 helper；无法可靠检查进程时报告错误，避免与未知服务同时修改系统时间。应用只取消并回收自己启动的进程组，不停止系统已有服务。helper 正常退出后时钟仍无效也视为失败，退出码 0 本身不等于授时成功。

运行包附带 **`assets/time/sync-busybox.sh`**，但默认不启用。它在前台执行 `/bin/busybox ntpd -n -q -p SERVER`，不安装、启动或停止全局服务。设备需要可执行的 `/bin/busybox` 且包含 `ntpd` applet、可用的 DNS 和到 NTP 服务的 UDP 123 通路。通常以 root 运行；按 capability 部署时，需 `CAP_SYS_TIME` 及该客户端绑定低端口所需的权限。缺少条件会明确失败，不自动安装系统工具。

在解包目录显式运行应用：

```sh
./run.sh --time-sync-helper "$PWD/assets/time/sync-busybox.sh" \
    --time-sync-timeout 60
```

服务器默认为 `pool.ntp.org`。可通过 `RV1126B_NTP_SERVER` 选择已有 NTP 服务器；脚本接受 DNS 主机名或 IPv4 地址，拒绝 URL、端口、参数、空白和其他字符，避免选项注入。IPv6 服务可通过 DNS 主机名使用，实际支持取决于目标 BusyBox 构建。

```sh
RV1126B_NTP_SERVER='time.example.net' \
    ./run.sh --time-sync-helper "$PWD/assets/time/sync-busybox.sh"
```

不要直接执行 helper 来测试参数：它具备修改系统时间的能力。需要现有系统服务、其他授时协议或不同 BusyBox 路径时，由设备维护者提供符合上述前台、无参数契约的 wrapper；程序不拼接 shell 命令。

## 排查与设备验证

先检查设备当前日期、路由、DNS、NTP 服务及工具能力；保留原有系统服务和配置。无效时间与超时场景应在隔离测试环境或维护窗口验证，避免回拨共享系统时钟影响其他应用。主机 mock 测试不能代替真实系统时钟、权限和 NTP 联网验证。

| 场景 | 通过条件 |
| --- | --- |
| 时间正常 | 网络就绪后直接继续启动 SDK，不启动 helper；不能将此结果记录为精确 NTP 同步 |
| 时间无效、系统服务存在 | UI 显示等待时间；已有服务完成校时后继续启动，不启动第二个客户端 |
| 时间无效、没有 helper | 仅等待系统校时；超出配置窗口后说明原因并非零退出，SDK 未启动 |
| 可选 helper 成功 | 无现成服务时只启动一个自有前台 helper；时间通过合理性检查后继续启动，进程正确回收 |
| helper 缺失/无执行权限 | 明确报告配置或启动错误并非零退出，不安装替代工具、不降低 TLS 验证 |
| helper 退出但时间仍无效 | 即使退出码为 0，仍报告失败并非零退出，不假定授时成功 |
| 已有 daemon 与显式 helper | 已有 `ntpd` / `chronyd` / `systemd-timesyncd` / `openntpd` 优先，配置的 helper 不运行，已有服务不被停止 |
| 网络断开及恢复 | 等待被取消，自有 helper 进程组回收；恢复后重新计算完整等待窗口，不消耗 AP 配网时间 |
| Ctrl-C/SIGTERM/配网切换 | 能取消等待和自有 helper，进程组无残留，系统已有校时服务仍运行 |
| 无权限、DNS 或 UDP 123 失败 | 屏幕/标准错误有失败或超时原因，SDK 不在无效时间下继续启动 |

记录版本、实际命令、等待窗口、是否启用 helper、已有时间服务、退出码及时间变化；公开日志前隐藏设备标识与其他凭据。实际的时间准确度需使用独立测量或系统授时工具确认，不能由 2026 门槛推断。
