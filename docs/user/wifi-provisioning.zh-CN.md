# AP Wi-Fi 配网

0.3.0 候选版内置 AP 配网。已有可用网络时直接沿用；离线启动时，在总计 30 秒内尝试已保存网络，失败或没有配置时开启热点。主机逻辑、协议与交叉构建检查不能证明目标设备的 AP、驱动并发、DHCP 和手机兼容性；该功能仍待设备验证，实际结果见[验证矩阵](../validation/README.md)。

## 设备前提

目标 Linux 系统需要：

- 支持 nl80211 AP 模式的 Wi-Fi 驱动；优先支持同一射频上的 AP+STA 虚拟接口组合。
- 可执行的 `ip`、`iw`、`hostapd`、`dnsmasq`、`wpa_supplicant`、`udhcpc`，以及 DHCP hook 使用的基础 shell 工具。运行包只内置 `assets/wifi/udhcpc.script`，不包含这些系统程序。
- 创建/配置网络接口、启动 DHCP、使用私有 `/run` 目录和绑定 HTTP 80、DNS 53 端口的权限。通常由 root 运行；不自动安装软件或更改系统服务。
- 正常的系统时间和 CA 配置，供后续 HTTPS 配对和 MyBot 服务使用。

可由设备操作者先检查：

```sh
for tool in ip iw hostapd dnsmasq wpa_supplicant udhcpc; do
    command -v "$tool" || break
done
iw dev
iw list
```

`iw list` 应列出 AP 模式；并发能力需结合 `valid interface combinations` 和实际启动确认。能列出 AP 不等于 AP+STA 能同时工作。若驱动不支持创建虚拟 AP，后端只在安全拥有 STA 的情况下退回单接口；已有外部 supplicant/hostapd 占用时明确报错，不会全局停止系统网络管理器。操作者需要按板级网络方案显式移交该接口，或使用仅监测模式。

## 手机操作

1. 正常运行 `./run.sh`；也可用 `./run.sh --wifi-provision` 强制进入配网。屏幕就绪后显示热点和访问地址。
2. 手机连接开放热点 **`mybot-xxxx`**。`xxxx` 为所选 STA MAC 前两个字节的小写十六进制；热点不设密码，按手机提示选择保持连接。
3. 等待 captive portal 弹出；未弹出时在浏览器打开 **`http://192.168.4.1/`**。
4. 从列表选择 2.4 GHz 网络，或手动填写网络名称以连接隐藏 SSID。输入密码；开放网络留空。页面支持中文/English 切换。
5. 点击连接并等待结果。候选连接在获取可用 IPv4 和路由后才保存；失败显示重试入口，不替换已有配置。单接口模式在连接尝试期间会暂时关闭热点，失败后重新连接 `mybot-xxxx` 再打开页面即可重试。
6. 页面确认连接成功后显示“完成”，约 1 秒后请求退出配网。控制器收到退出请求后留出响应时间；即使浏览器离开，成功状态最多保持约 5 秒后自动结束。热点关闭，MyBot 恢复启动并继续原有配对/会话流程。单接口模式成功时手机可能先失去热点，直接观察设备恢复业务。

门户的“已保存的网络”支持设置默认与删除；默认网络在列表首位。最多保存 10 项，连接成功的新网络成为默认。删除默认项后，下一项成为默认；删除仅修改本应用的缓存，不会改写系统网络管理器自己的配置。

热点是临时开放网络；配网结束后自动关闭。SSID 和密码只通过本地 HTTP 请求正文提交，不放入 URL，也不写入应用日志。加密网络保存派生 PSK，存于私有 `MYBOT_KV_STORE_DIR/wifi/wifi.credentials`（文件 0600、目录 0700）；派生 PSK 仍属于敏感凭据，请勿上传或公开备份。

## 手动重新配网

运行过程中持续按住触屏或 Menu 键 **3 秒**，释放后不会额外开始/挂断一次会话；前台终端也可输入 `w` 后 Enter。应用主循环先停止 SDK 和当前会话，再进入 AP；完成后按既有绑定恢复 SDK，仍需短触或 Menu 短按显式开始会话。

```sh
# 指定无线接口并在启动时进入配网
./run.sh --wifi-interface wlan0 --wifi-provision

# 由系统网络管理器负责联网，本应用只监测
./run.sh --no-wifi-provisioning
```

`RV1126B_WIFI_INTERFACE` 等价于 `--wifi-interface` 的环境默认值。`--interface` / `RV1126B_INTERFACE` 是 SDK 的网络监测/路由过滤条件，与配网接口分开；若过滤到另一没有网络的接口，配网成功也不能让 SDK 就绪。`--no-wifi-provisioning` 与 `--wifi-provision` 不能同时使用；UI 演示不启动配网服务。

## 排查

| 现象 | 检查 |
| --- | --- |
| 缺少工具 / Missing required Wi-Fi tool | 由目标系统提供对应程序和兼容构建，确认 PATH；包内 DHCP hook 不代替系统工具 |
| No nl80211 Wi-Fi interface | 检查驱动/固件和 `iw dev`，用 `--wifi-interface` 指定真实无线接口 |
| Driver cannot create an AP+STA interface | 查看驱动并发组合和现有接口；若外部管理服务拥有 STA，需要人工移交，应用不会抢占 |
| hostapd did not enable the AP | 检查监管域、2.4 GHz 信道、驱动和工具兼容性；现有 STA 位于 5/6 GHz 时先改用 2.4 GHz |
| Cannot bind Wi-Fi portal sockets | 检查 `192.168.4.1` 已配置、80/53 端口占用与权限；避免与另一门户/DNS 服务抢占相同地址 |
| 热点可见但手机拿不到地址 | 检查 dnsmasq、驱动和手机 DHCP；这需要设备证据，主机测试不能代替 |
| 手机不弹页面 | 连接热点后手动打开 HTTP 地址，确认没有因“无互联网”提示自动切换回其他网络 |
| 扫描列表为空 | 单接口模式只读取扫描缓存，可手动输入 SSID；隐藏网络本来也可能不显示 |
| 错误密码后没有立即显示失败 | 一次连接有最多 30 秒预算；单接口模式需等待热点恢复后重新连接手机 |
| 配网成功但业务不通 | 检查设备默认路由、DNS、时间、CA、服务地址及显式 SDK 接口过滤；获得路由并不证明云端服务可达 |
| 已连接但重启后不能复用 | 检查私有存储权限、可写性与退出附近错误；保存失败不会伪装成已持久化，不要通过删除绑定目录修复 |

## 设备验证

由操作者使用本候选包执行并记录。需要保留原有凭据时，先使用独立的测试 `MYBOT_KV_STORE_DIR`；这也会形成独立的 MyBot 绑定，不要删除正式目录来制造“首次启动”。测试会改变所选 Wi-Fi 接口的运行状态。

| 场景 | 通过条件 |
| --- | --- |
| 已有网络正常启动 | 无需配网即可恢复原有业务，不创建热点、不改动已有网络；缺少 AP 工具不影响已有网络启动 |
| 无缓存且无可用网络 | 显示热点/地址，手机取得地址，captive browser 或手动 HTTP 入口可访问 |
| 强制配网 | `--wifi-provision` 开启配网；所选接口与 `--wifi-interface` 一致 |
| 错误密码与重试 | 页面有连接中状态；失败后可重试，正式缓存不被错误候选覆盖；单接口路径热点可恢复 |
| 正确密码 / 开放 / 隐藏网络 | 获得可用 IPv4 与路由后完成；正常退出热点并恢复业务；隐藏 SSID 可手工输入 |
| 保存与重启 | 候选成功后生成私有配置，重启可复用；设置默认/删除与列表一致，失败网络不写入缓存 |
| 会话中手动配网 | 3 秒触屏/Menu 长按或终端 `w` 先结束 SDK/音频/视频，再启动 AP；完成后绑定保持且可再次开聊 |
| 中英文与 captive browser | 手机页面切换语言，长/中文/引号 SSID 显示为文本；刷新、失败提示与完成行为正确 |
| 退出与清理 | 配网中 Ctrl-C/SIGTERM 能退出；本应用 HTTP/DNS、AP、DHCP 与拥有的子进程清理，外部服务仍运行，再次启动无端口/接口残留 |
| 升级/回退 | 原绑定不丢失，两个版本不可同时运行；使用旧版时保留新增加的私有 Wi-Fi 缓存 |
